# world.execute(me); — code remake

We are recreating the fan MV `../qV0aezH6Aj8.mp4` (not in the repository; 3:32, 1920x1080, 60 fps, Mili "world.execute(me);", 130 BPM) entirely in code. The goal is a frame-faithful remake: shown side by side with the original it should read as the same video — same layout, typography, palette, motion and timing. Several agents work in parallel, each owning one segment of the timeline.

## Engine

`engine/stage.html` is a 1920x1080 page. For song time `t` (seconds) the runtime mounts every scene whose `[start, end)` contains `t`, stacks them by `z`, and calls `render(t)`. Frames are captured by headless Chrome (GPU) and encoded with ffmpeg; the song is muxed in.

A scene is an ES module `scenes/<segment>/<name>.scene.js` (only `*.scene.js` files are scenes; anything else in your folder is a helper):

```js
export default {
  id: 'math/sine',              // '<segment>/<name>'
  start: 36.95,                 // song seconds, inclusive
  end: 42.2,                    // exclusive
  z: 0,                         // optional, for scenes that overlap in time
  fonts: ['400 40px "JetBrains Mono"'],   // optional: loaded before the first render (needed for canvas text)
  async create(root, env) {     // root: absolutely positioned 1920x1080 <div>
    // build DOM / canvas / WebGL once, precompute everything here
    return {
      ready: somePromise,       // optional
      render(t) { /* show the state at absolute song time t */ },
      destroy() {},             // optional
    };
  },
};
```

**`render(t)` must be a pure function of `t`.** Workers render chunks in parallel and stills are taken at arbitrary times, so a scene can be created fresh at any `t` and frames are not visited in order. That rules out `Math.random` (use `env.rng(seed)`), `Date.now`/`performance.now`, `requestAnimationFrame`, timers, and CSS transitions/animations (if you want a CSS keyframe animation, pause it and seek it: `animation-play-state: paused; animation-delay: -<seconds>s`). Simulations (pendulums, Lorenz, Game of Life, DLA, Tetris, …) are precomputed deterministically in `create()` and looked up by `t`. Keep `render(t)` cheap (aim < 30 ms); a full render is 12,738 frames.

`env` provides: `W`, `H`, `beat` (`BPM`, `BEAT0`, `SPB`, `beatAt(t)`, `timeAt(beat)`, `barAt(t)`), `anim` (`clamp`, `lerp`, `invLerp`, `prog(t, t0, len)`, `smoothstep`, `ease.*`, `rng`, `typed(text, t, t0, cps)`), `rng(seed)`, `canvas(root, { context: '2d'|'webgl'|'webgl2'|null, width, height, options })`, `loadFont(family, url)`, `loadImage(url)`, `loadJSON(url)`. Modules can also be imported relative to your scene file, e.g. `import { ease } from '../../engine/lib/anim.js'`.

URLs: the site may be served under a path prefix (GitHub Pages), so never hand a host-absolute path to `fetch`, `FontFace` or `import`. Use relative imports and `new URL('./x', import.meta.url).href`, or pass `/scenes/...` to `env.loadJSON`/`env.loadFont`/`env.loadImage`, which resolve it against the project root.

Anything goes inside a scene: DOM/CSS (the right tool for UI mockups such as terminals, chat apps, IDEs, htop — build real HTML and update it in `render(t)`), Canvas 2D, WebGL. Third-party libraries (three.js, d3-geo, topojson…) must be downloaded as ES-module builds into `scenes/<segment>/vendor/` — no CDN at render time, no npm installs in the project.

`scenes/math/sine.scene.js` is a small working example.

**Beat grid**: 130.00 BPM, beat 0 at 0.1396 s (`env.beat.timeAt(b)`). Hard cuts in the original land on this grid (often on 1- or 2-beat boundaries), and key words usually land on beats. When the reference shows an event near a beat, snap to it.

## Fonts

Every family under `assets/fonts/` is available by name in CSS and canvas: JetBrains Mono, IBM Plex Mono, Fira Code, Geist Mono, Red Hat Mono, Roboto Mono, Ubuntu Mono, Share Tech Mono, Courier Prime, VT323, Press Start 2P, DotGothic16, Nabla, EB Garamond, Cormorant Garamond, Latin Modern Roman, Roboto, Roboto Condensed, Libre Franklin, Plus Jakarta Sans, Michroma. (Only the families the scenes use are kept; fetch others as below.) System fonts work too: Noto Sans/Serif CJK KR/JP/SC/TC, Noto Serif, Noto Sans Mono, Source Code Pro, Inter, Liberation Sans/Serif/Mono.

Need another Google Font? `python3 -P -E tools/fetch_fonts.py ofl/<dir>` (folder names as in github.com/google/fonts) — it is usable by name right away (`/assets/fonts/fonts.css` is generated by the server from the folders). Pick the closest match to the original; list substitutions in your report.

## Tools (run from `mv/`)

| What | Command |
|---|---|
| Contact sheet of the original | `python3 -P -E tools/sheet.py --from A --to B --n 18 --cols 6 --width 320 --out out/<seg>/sheet.png` (or `--times t1,t2 --width 960`) |
| One full-res original frame | `ffmpeg -loglevel error -ss T -i ../qV0aezH6Aj8.mp4 -frames:v 1 out/<seg>/ref_T.png` |
| Frame-exact event times in a region | `python3 -P -E tools/events.py --from A --to B --region x0,y0,x1,y1 [--k 1.5] [--trace]` |
| **Original vs ours, side by side** | `python3 -P -E tools/compare.py --times t1,t2,... --only <seg>/ --out out/<seg>/cmp.png [--width 640]` (prints mean-abs-diff per pair) |
| Stills | `node tools/render.mjs --stills t1,t2 --only <seg>/ --outdir out/<seg>/stills` |
| Clip with audio | `node tools/render.mjs --from A --to B --only <seg>/ --out out/<seg>/clip.mp4 --workers 2` (`--scale 0.5` for a fast preview) |
| Validate / list scenes | `node tools/render.mjs --list --only <seg>/` |
| Whole-video fidelity scan | `python3 -P -E tools/scan_full.py out/v3/world-execute-remake-v3.mp4 out/scan` (per-scene, per-frame and per-tile error vs the original; `tools/sheets.py <video> out/scan out/sheets` draws the worst frames) |
| Did a change get closer? | `python3 -P -E tools/score.py out/<seg>/clip.mp4 --from A [--region x0,y0,x1,y1] [--per-frame]` (vs the original and vs the full render in `out/v3/`) |
| Original above ours, many times | `python3 -P -E tools/pairs.py --from A --to B --step 0.25 --out out/<seg>/pairs.jpg [--video clip.mp4 --clip-from A] [--diff]` |
| Event timing per tile | `python3 -P -E tools/event_lags.py <video> out/events` (early/late/missing changes vs the original) |
| Determinism | `python3 -P -E tools/determinism.py out/determinism` (same times in three orders must give identical PNGs) |

Exit code 2 means a scene threw: the error is printed and drawn over the scene in the frame. Python: use `python3 -P -E`; cv2/numpy live in user site-packages, which `-I` hides. Sample colours from reference frames with cv2.

## Working loop

1. Study your segment: contact sheets (a coarse one, then dense ones around every event), full-res frames for detail, `events.py` for timings. Write down a shot list with exact times before coding.
2. Build scene by scene. After each meaningful change run `compare.py` at the timestamps that matter (start, end, every reveal/transition, a few in between) and fix what differs: positions, sizes, colours, fonts, easing, timing.
3. When a scene matches, move on; come back for polish if time allows.
4. Finish by rendering your whole segment as a clip (`--workers 2`), confirm exit code 0, and run a final `compare.py` over ~8–12 timestamps spread across the segment.

## Rules

- Write only inside `scenes/<your segment>/`, `out/<your segment>/`, and new font folders created with `tools/fetch_fonts.py`. Don't edit `engine/`, `tools/`, `assets/` files that exist, other segments, or `AGENTS.md`. If the engine is missing something, work around it inside your segment and say so in your report.
- Your scenes must cover your assigned range(s) exactly — first `start` = range start, last `end` = range end, no gaps. Overlaps are allowed only between your own scenes.
- Other agents render at the same time on 8 cores and one iGPU: use `--workers 2` at most, iterate with stills and `compare.py` and leave full clips for the end, and never kill processes you didn't start.
- Images cost context: prefer compare grids of 4–8 pairs at `--width 640`, crop/zoom only where you need detail.
- No sudo, no global installs, no edits outside the project.

## Report (your final message, ≤ 400 words)

- Scenes: `id`, `start–end`, what it shows, technique.
- Fidelity: what matches; what still differs, concretely; font substitutions.
- Verification: final clip path, exit code, final compare grid path and the mean-abs-diff range.
- Anything another segment or the integrator needs to know (boundary state, engine wishes).
