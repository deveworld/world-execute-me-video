# world.execute(me); — live web viewer

The viewer runs the existing scene modules in a 1920×1080 iframe. Its timeline calls `__stage.renderFrame(t)` at the selected frame rate. The visuals are the DOM, SVG, Canvas and WebGL scenes from `../mv`. The soundtrack is the playback clock (see **Sound**).

Run `npm run build` to copy the current scene implementation and fonts, extract the soundtrack from `../qV0aezH6Aj8.mp4` when that file exists, and render the seek-bar thumbnails (`thumbs.mjs`, about 40 s, skipped when the copied scenes are unchanged; it needs `npm install` in `../mv`, Google Chrome and ffmpeg). Run `npm start` and open `http://127.0.0.1:4173`.

The page shows only the stage and a floating playback bar. The bar fades out after 2.5 s without pointer movement and comes back on mouse movement, a tap or a key press. It stays visible while the pointer is over it or the YouTube player, or while a menu is focused. Clicking the stage plays or pauses, and double-clicking toggles fullscreen. Keys: Space/K play/pause, ←/→ seek five seconds, comma/period step one frame, M mute, Y show/hide the YouTube player, F fullscreen. The time field accepts `m:ss.mmm` or seconds. Timestamp links use `?t=16` in seconds. On slower devices the sound keeps time and visual frames are skipped.

**Resolution** sets how many device pixels the stage is drawn on. "화면 맞춤" fills the window at its device resolution. A fixed size (3840×2160 … 640×360) is drawn 1:1, centred, the same as `render.mjs --scale`. If the window is smaller than that size, the stage is fitted and the bar says so. Above 1080p, 2D canvases are drawn at 1.5 or 2 device pixels per stage pixel (`engine/hidpi.js`), so canvas text and lines stay sharp too; a change of scale creates every scene again. WebGL canvases (the CRT screens, the iris texture) stay at 1920×1080. At scale 2 the cache keeps up to 2.5 GB of canvases, the scenes nearest the playhead.

**fps** sets the rate at which `render(t)` is sampled (24, 30, 60 = original, 120, 144, 240). Frame k is song time k/fps. The timeline and frame steps use the chosen rate, and rates above the display refresh rate skip frames. Both settings are kept in localStorage; `?res=1280x720&fps=30` overrides them for one visit.

**Seeking.** The viewer loads `viewer/stage.html`, whose runtime (`viewer/runtime.js`) is the engine runtime plus a scene cache. A scene that goes out of range stays mounted but hidden, so returning to it is a single `render(t)` call. While the viewer is idle, it creates scenes ahead of time, nearest to the playhead first. When paused it covers the whole song in about 4 s; while playing it covers the next 8 s. With the cache warm, a random seek takes one or two display frames. Errors from scenes created in the background are only reported when that scene is shown. The renderer keeps using `engine/stage.html`.

**Preview.** Hovering over or dragging the seek bar shows a thumbnail and the time. Thumbnails are rendered from the same scene code by `../mv/tools/render.mjs` at 4 per second (320×180, in 10×10 JPEG sheets under `dist/media/thumbs`).

**Sound.** With `dist/media/soundtrack.m4a` (local builds that have the original video), an `<audio>` element plays it and its `currentTime` is the clock. Without it (the published site), `youtube.js` embeds Mili's official upload (`ESx_hy1n7HA`). The iframe API reports YouTube's time only every few hundred milliseconds, so the player runs its own clock and steers it toward YouTube's. The clock holds while YouTube starts, seeks or buffers. After that it runs at most 5% faster or slower until the two agree, and it jumps when they are more than 0.3 s apart. If YouTube does not start within 3 s (10 s while buffering), for example because autoplay is blocked, the scenes play on silently. Pressing play on the YouTube player then brings the sound in at the current time. Play and pause pressed on the YouTube player itself are followed. The YouTube player sits in the top-right corner and is hidden when the bar fades; only Y or the bar button brings it back, until the bar fades again. It is also shown while the scenes play silently and wait for that press. `?audio=youtube` forces YouTube locally.

**Paths.** All URLs are relative, so `dist/` works under any path prefix (GitHub Pages serves it at `/world-execute-me-video/`). Scenes keep writing `/scenes/...` for `env.loadJSON`, `env.loadFont` and `env.loadImage`; the runtimes resolve those against the project root. The Pages workflow (`.github/workflows/pages.yml`) runs `node prepare.mjs --check-thumbs`. That copies `../mv`, writes the scene index and font CSS, and fails if the committed thumbnails no longer match the scenes. In that case, run `npm run build` locally and commit `dist/media/thumbs`.

**Test.** With `npm start` running, `npm test` drives the viewer in headless Chrome (playwright-core from `../mv/node_modules`): bar visibility, layout at each resolution, fps and frame stepping, mobile layout, prewarm and seek timing, and pixel identity between `viewer/runtime.js` and the engine runtime. Screenshots and `result.json` go to `output/test/`.

Every build replaces `dist/engine`, `dist/scenes` and `dist/assets` with fresh copies from `../mv`, so edit scenes in `../mv` and rebuild.
